# MineSkynet 프로젝트 원칙

1. **논문 언어를 먼저 쓴다.** 모든 기술 항목은 그것이 보존·검증하는 논문 개념과 연구 목적을 비전공자도 이해할 수 있는 한 문장으로 먼저 설명하고, 구현·dependency·검증 세부사항은 그 아래에 배치한다.

2. **연구 질문을 기준으로 범위를 정한다.** 최종 목적은 MineSkynet 가설 검증이며 Odyssey 현대화는 구형 의존성으로부터 안전하고 반복 가능한 연구 기반을 만드는 수단이다. `master`는 원본 기능의 source reference로 사용하고 legacy와 modernized의 속도 경쟁을 별도 연구로 확대하지 않는다.

3. **격리와 제거를 구분해 선행연구 기능을 보존한다.** 논문·Voyager의 핵심 기능은 무겁거나 구형 dependency를 사용한다는 이유만으로 삭제하지 않고 baseline·optional·Full profile로 분리하며, Sentence Transformer·Chroma·LangChain처럼 신뢰받는 외부 구현은 명확한 결함과 contract 회귀 근거 없이 재작성하지 않는다.

4. **연구자의 판단과 작업 권한을 넘겨짚지 않는다.** 논문 해석, 연구 범위, 평가 기준처럼 결과의 의미를 바꾸는 선택은 근거와 선택지를 제시해 연구자에게 넘기고, 로그인·권한 승인·대화형 조작·장시간 서비스 관찰처럼 연구자가 직접 수행해야 하는 터미널 작업은 실행 명령과 확인할 결과를 함께 전달한다.

5. **문서는 세 독자와 증거 수준에 맞춰 한 번만 쓴다.** 직접 연구자, 교수·동료 평가자와 프로젝트를 모르는 제3자가 상위 문서만으로 목적·현재 상태·다음 결정을 이해하게 하고, 세부 구현과 원시 증거는 링크로 내려보내며 중복 문서·과도한 분할·component 성공의 전체 완료 표기를 만들지 않는다.

6. **문서의 업데이트시 현재 연구자 시각의 완료 시점에 맞춰 갱신한다.** 과거 완료 기록은 제거하거나 해당 세부사항에 한줄로 요약하고, 지나치게 많은 '현재 완료'를 방지한다. 한편, 연구자가 다시 복귀하였을 때 최근 진행사항을 더 간결하게 파악할 수 있도록 돕는다.
